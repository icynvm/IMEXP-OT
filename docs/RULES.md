# กฎของระบบ

กฎทุกข้อถูกบังคับที่ **ฐานข้อมูล** ([`supabase/migrations/20261007000000_init.sql`](../supabase/migrations/20261007000000_init.sql))
หน้าเว็บตรวจซ้ำอีกชั้นเพื่อแจ้งข้อความภาษาไทยให้อ่านง่าย ([`src/lib/validation.ts`](../src/lib/validation.ts))
ดังนั้นต่อให้มีคนพยายามข้ามหน้าเว็บ ก็บันทึกข้อมูลที่ผิดกฎไม่ได้

## 1. คำขอทำ OT

| กฎ | รายละเอียด |
| --- | --- |
| ช่วงเวลา | **ก่อนเริ่มงาน**: ต้องจบไม่เกิน 09:00 / **หลังเลิกงาน**: ต้องเริ่มตั้งแต่ 18:00 |
| ความละเอียดเวลา | ทีละ 30 นาที (18:00, 18:30, …) |
| จำนวนชั่วโมง | คำนวณอัตโนมัติจาก เวลาสิ้นสุด − เวลาเริ่ม (กรอกเองไม่ได้ กันตัวเลขไม่ตรง) |
| ห้ามซ้อน | ช่วงเวลาซ้อนกับคำขอเดิมในวันเดียวกัน (ที่ยังรออนุมัติหรืออนุมัติแล้ว) ไม่ได้ |

## 2. คำขอใช้ชั่วโมง OT

| กฎ | รายละเอียด |
| --- | --- |
| แหล่งชั่วโมง | ใช้ได้เฉพาะ OT ที่ **อนุมัติแล้ว** และ **ทำไปแล้ว** (วันที่ทำ OT ≤ วันนี้) |
| ตัดหลายวันได้ | 1 คำขอใช้ ตัดจาก OT หลายวันได้ ปกติกรอกจำนวนชั่วโมงช่องเดียว ระบบแบ่งให้อัตโนมัติ (เก่าสุดก่อน) หรือกด "เลือกเองว่าจะตัดจาก OT วันไหน" (เว้นว่าง = ข้าม OT วันนั้น) |
| ความละเอียด | ทีละ 0.5 ชั่วโมง |
| ห้ามเกิน | ใช้เกินยอดคงเหลือของ OT วันนั้นไม่ได้ |
| ยกเลิก | เจ้าของยกเลิกได้เฉพาะตอน **รออนุมัติ** → ชั่วโมงคืนเข้ายอดทันที |

## 3. วิธีคำนวณยอด

ยอดไม่ได้ถูก "เก็บเป็นตัวเลข" แต่ **คำนวณใหม่ทุกครั้ง** จากรายการจริง (view `ot_request_balances`) จึงไม่มีทางเพี้ยน

สำหรับ OT ที่อนุมัติแล้วแต่ละรายการ:

```
ได้รับ        = ชั่วโมงของคำขอ OT
ใช้แล้ว       = ผลรวมชั่วโมงที่ตัดไป ในคำขอใช้ที่ "อนุมัติแล้ว"
จองไว้        = ผลรวมชั่วโมงที่ตัดไป ในคำขอใช้ที่ "รออนุมัติ"
คงเหลือ       = ได้รับ − ใช้แล้ว − จองไว้
```

**ทำไมต้อง "จอง"?** กันการยื่นใช้ชั่วโมงเดียวกันซ้ำหลายครั้งระหว่างรอหัวหน้าอนุมัติ
ถ้าไม่อนุมัติหรือยกเลิก ชั่วโมงที่จองจะกลับเป็น "คงเหลือ" อัตโนมัติ

ตัวอย่าง:

| เหตุการณ์ | OT 1 ต.ค. (3.5 ชม.) | OT 2 ต.ค. (2 ชม.) | คงเหลือรวม |
| --- | --- | --- | --- |
| หัวหน้าอนุมัติ OT ทั้งสอง | เหลือ 3.5 | เหลือ 2 | 5.5 |
| ขอใช้ 4 ชม. (แบ่งอัตโนมัติ) | จอง 3.5 → เหลือ 0 | จอง 0.5 → เหลือ 1.5 | 1.5 |
| หัวหน้าอนุมัติการใช้ | ใช้แล้ว 3.5 | ใช้แล้ว 0.5 → เหลือ 1.5 | 1.5 |

## 4. สิทธิ์ของแต่ละบทบาท

| | พนักงาน | หัวหน้าทีม | หัวหน้าแผนก | admin |
| --- | :---: | :---: | :---: | :---: |
| ขอทำ OT / ขอใช้ OT ของตัวเอง | ✅ | ✅ | ✅ | ✅ |
| คำขอของตัวเอง | รอหัวหน้าอนุมัติ | **อนุมัติอัตโนมัติ** | **อนุมัติอัตโนมัติ** | **อนุมัติอัตโนมัติ** |
| ดู / อนุมัติคำขอของคนอื่น | | ลูกทีม | ทุกคนในแผนก | ทุกคน |
| ภาพรวม + ดาวน์โหลด CSV | | ทีม | แผนก | ทั้งหมด |
| ตารางวันหยุด: ใครหยุดวันไหน | ✅ ทุกคน | ✅ ทุกคน | ✅ ทุกคน | ✅ ทุกคน |
| ตารางวันหยุด: รายละเอียด | ของตัวเอง | ลูกทีม | ทุกคนในแผนก | ทุกคน |
| จัดการผู้ใช้ / แผนก | | | | ✅ |

- **ลูกทีม** = ผู้ใช้ที่ช่อง "หัวหน้าผู้อนุมัติ" เป็นหัวหน้าคนนั้น (admin ตั้งในหน้าจัดการผู้ใช้)
- **ทุกคนในแผนก** = ผู้ใช้ที่ช่อง "แผนก" เป็นแผนกที่หัวหน้าแผนกคนนั้นดูแล (admin ตั้งในหน้าจัดการผู้ใช้ / หน้าแผนก)
- 1 แผนกมีหัวหน้าแผนก 1 คน และ 1 คนเป็นหัวหน้าได้ 1 แผนก
- **ไม่อนุมัติ** ต้องใส่เหตุผลเสมอ
- คำขอที่อนุมัติอัตโนมัติ บันทึกหมายเหตุ "อนุมัติอัตโนมัติ (หัวหน้ายื่นเอง)" ไว้ตรวจสอบย้อนหลังได้
- admin ลดสิทธิ์หรือปิดบัญชีตัวเองไม่ได้ (กันระบบไม่มี admin เหลือ)
- จะเปลี่ยนบทบาทของคนที่เป็นหัวหน้าแผนกอยู่ ต้องเปลี่ยนหัวหน้าในหน้าแผนกก่อน
- เข้าสู่ระบบได้ทั้ง **อีเมล** หรือ **รหัสพนักงาน** (admin แก้รหัสพนักงานแล้ว ต้องใช้รหัสใหม่ login) · กรอกผิดจะแจ้งข้อความเดียวกันเสมอ ไม่บอกว่ารหัส/อีเมลนั้นมีในระบบหรือไม่
- บัญชีที่ถูก **ปิดการใช้งาน** login ได้แต่ใช้งานอะไรไม่ได้ ข้อมูลเดิมยังอยู่ครบ

## 5. การแจ้งเตือน (อีเมล + Push + กระดิ่ง)

| เหตุการณ์ | ส่งถึง (อีเมล และ Push ที่มุมจอสำหรับอุปกรณ์ที่เปิดแจ้งเตือนไว้) |
| --- | --- |
| พนักงานยื่นคำขอทำ OT / คำขอใช้ OT | หัวหน้าผู้อนุมัติ → ถ้าไม่มี: หัวหน้าแผนก → ถ้าไม่มี: admin ทุกคน |
| หัวหน้า / admin ยื่นคำขอเอง | ไม่ส่ง (อนุมัติอัตโนมัติ) |
| อนุมัติ / ไม่อนุมัติ | พนักงานเจ้าของคำขอ |

ถ้าส่งอีเมล/Push ไม่สำเร็จ การยื่นคำขอ/อนุมัติ **ยังสำเร็จตามปกติ** (ระบบบันทึก log ไว้ให้ตรวจสอบ)

- **กระดิ่ง** (มุมบนของเมนู): เฉพาะหัวหน้าทีม / หัวหน้าแผนก / admin — แสดงคำขอที่รอตัวเองอนุมัติ (ล่าสุด 20 รายการ)
  ตัวเลขแดง = จำนวนที่รออนุมัติ, จุดน้ำเงิน = รายการใหม่ตั้งแต่เปิดดูครั้งก่อน, อัปเดตเองทุก 1 นาทีและทุกครั้งที่กลับมาที่หน้าเว็บ
- **Push**: ต้องกด "เปิดการแจ้งเตือน" บนอุปกรณ์นั้นก่อน (ที่กระดิ่ง หรือหน้าโปรไฟล์) — กดที่การแจ้งเตือนจะเปิดหน้าที่เกี่ยวข้อง
  ขณะเปิดเว็บค้างไว้แต่ดูแท็บอื่น หน้าเว็บเด้งแจ้งเตือนเองด้วย (ไม่ซ้ำกับ Push เรื่องเดียวกัน)
- **ติดตั้งเป็นแอป (PWA)**: หน้าโปรไฟล์ → ติดตั้งแอป / iPhone: Safari → แชร์ → เพิ่มไปยังหน้าจอโฮม
  เปิดแบบแอปเต็มจอ มีทางลัด "ขอทำ OT / ขอใช้ OT / รออนุมัติ" และหน้าแจ้ง "ไม่มีอินเทอร์เน็ต" เมื่อเน็ตหลุด

## 6. ตารางวันหยุด และวันหยุดนักขัตฤกษ์

- **ตารางวันหยุด** (เมนูของทุกคน) แสดง 2 อย่าง: วันหยุดนักขัตฤกษ์ (ตัวเลขสีแดง) และวันที่พนักงานใช้ชั่วโมง OT หยุดงานที่อนุมัติแล้ว (จุดสีน้ำเงิน)
- ทุกคนเห็นว่าใครหยุดวันไหน · กดดูรายละเอียดได้เฉพาะหัวหน้าทีมขึ้นไป และเฉพาะคนที่ตัวเองดูแล · พนักงานทั่วไปกดดูรายละเอียดไม่ได้
- โหลดข้อมูลล่วงหน้า 12 เดือนก่อน-หลัง จึงเลื่อนเดือนได้ทันที
- **วันหยุดนักขัตฤกษ์** ใส่ข้อมูลปี 2569–2570 ไว้ให้แล้ว (ตามวันหยุดธนาคาร/ภาคเอกชน ไม่รวมวันเข้าพรรษาที่หยุดเฉพาะราชการ)
  admin เพิ่ม/แก้/ลบได้ที่เมนู **วันหยุดนักขัตฤกษ์** — ควรเพิ่มของปีถัดไปเมื่อ ครม./ธนาคารแห่งประเทศไทยประกาศ
- วันหยุดใช้แสดงผลเท่านั้น ยังไม่มีผลกับการคำนวณ OT

## 7. โปรไฟล์

- ทุกคนแก้ **ชื่อ-นามสกุล** และ **รูปโปรไฟล์** ของตัวเองได้ที่เมนู **โปรไฟล์** (หรือกดที่ชื่อมุมล่างซ้าย) หลังสมัครแล้ว
- รหัสพนักงาน, อีเมล, บทบาท, แผนก, หัวหน้า เปลี่ยนได้โดย admin เท่านั้น
- รูปโปรไฟล์: ระบบตัดเป็นสี่เหลี่ยมจัตุรัสและย่อเป็น 512×512 px ในเครื่องผู้ใช้ก่อนอัปโหลด (ไม่เกิน 1 MB, JPG/PNG/WebP)
  เก็บใน Supabase Storage bucket `avatars` โฟลเดอร์ของผู้ใช้เอง — อัปโหลด/ลบได้เฉพาะของตัวเอง, เปลี่ยนรูปแล้วไฟล์เก่าถูกลบอัตโนมัติ
- รายการที่อนุมัติ/ไม่อนุมัติแล้ว แสดง **ชื่อผู้พิจารณา** เสมอ (แม้เป็นหัวหน้าแผนกหรือ admin ที่ไม่ใช่หัวหน้าโดยตรง)

## 8. ความปลอดภัย

| ป้องกันอะไร | ทำอย่างไร |
| --- | --- |
| เดารหัสผ่าน | กรอกผิด 8 ครั้งใน 15 นาที (จากเครื่อง/เครือข่ายเดียวกัน กับบัญชีเดียวกัน) → ต้องรอ 15 นาที แม้รหัสถูกก็เข้าไม่ได้ระหว่างนั้น · ผิดรวมทุกบัญชีจาก IP เดียว 30 ครั้ง → รอ 15 นาที · เจ้าของบัญชีที่อยู่เครื่องอื่นยังเข้าได้ปกติ (คนแกล้งกรอกผิดล็อกบัญชีคนอื่นไม่ได้) |
| สมัครถี่ / สแปม | สมัครได้ 20 ครั้ง/ชั่วโมง ต่อเครือข่าย |
| ยิงอีเมลลืมรหัสผ่าน | 10 ครั้ง/ชั่วโมง ต่อเครือข่าย และ 3 ครั้ง/ชั่วโมง ต่ออีเมล (เกินแล้วไม่ส่ง แต่ตอบเหมือนเดิม ไม่บอกว่าอีเมลมีในระบบหรือไม่) |
| คนนอกบริษัทสมัคร | admin ตั้ง "โดเมนอีเมลที่สมัครได้" ที่หน้าจัดการผู้ใช้ — ฐานข้อมูลตรวจเอง กันได้แม้สมัครผ่าน API ตรง |
| ฝังโค้ดอันตราย (XSS) | ข้อความทุกช่องแสดงเป็นตัวอักษร + CSP: เบราว์เซอร์รันเฉพาะ script ของเว็บเราที่มีรหัส (nonce) สุ่มใหม่ทุกครั้ง |
| ฝังหน้าเว็บใน iframe / ส่งฟอร์มไปเว็บอื่น | CSP `frame-ancestors 'none'`, `form-action 'self'` + X-Frame-Options |
| แก้/อ่านข้อมูลคนอื่นผ่าน API ตรง | สิทธิ์อยู่ในฐานข้อมูล (RLS + ฟังก์ชัน) — ทดสอบด้วย `npm run test:security` |

ตัวเลขจำกัดครั้งแก้ได้ที่ `src/lib/rate-limit.ts`
